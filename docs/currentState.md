# NodeWeave — Project Handover

**Snapshot date:** 2026-11-12  
**Purpose:** Describe the current implementation, distinguish real behavior from demo/fallback behavior, and give the next developer a prioritized verification and improvement list.

## 1. Product and current shape

NodeWeave is a client-side knowledge-map workspace. It accepts text, Markdown, and PDF sources, asks a Vercel serverless endpoint to draft a structured map, and offers Graph, Tree, and Doc views over the same map. A separate working copy supports manual edits without mutating the imported/generated original. Data is exported as JSON rather than stored in a server database.

The earlier implementation decisions and visual/interaction choices are recorded in [decisions.md](./decisions.md). This handover is an implementation-status document, not a replacement for the PRD, TRD, or design spec.

## 2. What exists

### Ingestion and map creation

- The boot tutorial leads to an uploader with Upload and Restore paths.
- `.txt` and `.md` files are read in the browser; PDFs are text-extracted client-side.
- New documents are sent to `POST /api/structure`. The handler uses Gemini server-side and returns the map. A large multi-document request is split by document and consolidated when the estimated text exceeds the endpoint's configured threshold.
- Text is chunked and embedded in-browser with Transformers.js. Semantic embeddings are included in exports when available.
- If embedding generation fails, the new map can still proceed; source chunks are retained with empty embeddings and chat can use keyword matching instead.
- Restoring one session is local. Restoring multiple sessions uses the `mode: "merge"` branch of `POST /api/structure`; custom insights are retained client-side and chunk IDs are namespaced per imported session.
- Imports accept legacy direct structure JSON and wrapped exports containing `original` or `working` plus `chunkStore`.

### Dashboard

- **Graph:** React Flow renders a d3-force simulation. Topics, subtopics, and custom insights have distinct visual treatments. Topics toggle child visibility on single click; double-click opens details. Hover shows node title/summary and edge reason.
- **Tree:** Three layouts (left-to-right, top-down, radial), expandable branches, optional descriptions/points, and cross-topic links. Cards can be repositioned in Edit mode; positions are retained per layout for the current page session.
- **Doc:** A book-like reader with topic chapters, subtopic sections, points, discrepancy notes, custom-insight callouts, and cross-topic connections. It omits session metadata.
- **Edit mode:** Changes are applied to a working copy. Node fields and structure, connections, and Tree positions can be edited. Graph dragging affects current simulation positions and is not a permanent layout.
- **Controls:** A collapsible left panel provides view-specific controls and shared filtering/search/focus/fit behavior. The header includes an accent selector and Chat/sidebar toggle. Accent choice is saved in `localStorage`; Edit mode is indicated by ambient styling rather than a status label.
- **Exports:** Original, modified, or both JSON files can be downloaded. Each includes the chunk store. The uploader can restore those exports.

### Chat

- `ChatPanel` sends the current query, a selected map slice, recent in-memory chat history, and up to five retrieved chunks to `POST /api/chat`.
- Chunk retrieval uses embeddings when available and keyword matching otherwise.
- The server uses Gemini and has an optional Groq fallback. Provider credentials remain server-side.
- The UI supports source-node citations, ASCII output, generated insight suggestions that can be pinned to the map, and a visible local keyword lookup if the API call fails.

## 3. Demo, fallback, and non-persistent behavior

- The uploader's **Test Loading Screen (35s)** button is a demonstration path: it waits 35 seconds and opens an empty map. It does not parse a source, call AI, or generate embeddings.
- `tests/magnetism-output-insights.json` is a demonstration fixture based on `tests/magnetism-output.json`; its three custom insights are hand-authored sample content, not generated by the chat API.
- The Miso greeting and the “sniffing” indicator are UI copy/animation. They do not represent a separate agent or background task.
- When `/api/chat` is unavailable or fails, the app may show a local keyword excerpt. This is a fallback, not an AI response.
- Browser state is not generally durable: the edited working copy, map layout positions, and chat transcript live in React state and are lost on reload. Only the accent theme is currently saved in `localStorage`. Export a session to preserve it.
- The `tests/test-chat.js` and `tests/test-structure.js` scripts are manual endpoint probes, not an automated suite. They expect a `test-data/` directory, which is not present in the repository; the chat script can make live provider calls if pointed at a deployed endpoint.

## 4. Known gaps and verification needs

### Must verify with a configured API environment

No live Gemini/Groq generation has been verified as part of this handover. The Vite dev server does not serve the Vercel `/api/*` functions, so chat and new-document structuring return an API error if run through Vite alone. The local Vercel CLI could not start because its saved authentication was rejected; the handler was instead exercised directly for method and invalid-request contracts. Use an authenticated `vercel dev` environment or a deployment configured with server-side provider credentials for an end-to-end check. Do not put credentials in frontend code or export them.

Before calling the AI workflows production-ready, verify:

1. New text/Markdown/PDF ingestion through `/api/structure`, including extraction quality and a real generated structure.
2. Both covered and uncovered `/api/chat` questions, citation correctness, exact refusal behavior, ASCII response rendering, insight suggestions, and provider fallback.
3. Multiple-session merge with overlapping topics and custom insights; check that preserved insight anchors still point to meaningful nodes when the model changes IDs.
4. Export/import round-trip with both ordinary and empty/keyword-only embeddings, then verify chat retrieval after restore.
5. Requests near Vercel function duration and payload limits, including large source files and embeddings in exports.

### Features described in product docs but not completed in the current UI

- Session AI-call budget/cap and usage counter are not implemented.
- Chat responses may contain correction metadata, but the chat UI does not currently present a correction/diff workflow or apply chat instructions as edits.
- AI-detected corrections are not wired into the working-copy edit pipeline.
- There is no general `localStorage` autosave/session list; use exports for persistence.
- Import validation is basic (required session name/topics and chunk shape checks), not full schema validation of every nested node, connection, and anchor.
- Merge preservation retains custom insights, but anchor remapping after model consolidation is not guaranteed. Verify this with different source IDs before relying on merge for edited maps.
- Comprehensive automated unit/integration tests are absent; `npm run build` is the available project validation script.
- Large graphs (50–100+ nodes), small-screen editing, keyboard/accessibility behavior, and PDF extraction across varied documents need broader testing.

## 5. Validation snapshot

Validation completed around this handover:

- `npm run build` — TypeScript and Vite production build pass.
- `git diff --check` — passes.
- Direct `/api/structure` handler checks passed for non-POST (405), empty documents (400), too few merge structures (400), and malformed merge structures (400). A valid merge request was intentionally not submitted because that would call the external model.
- Manual browser checks on the sample fixture verified Graph nodes/edges, node tooltip, topic collapse/expand, edge explanations with no arrowheads, the Doc reader and all three fixture insights, and Chat hide/reopen behavior.
- All three Tree layouts were checked for card overlap on the sample map; none were observed in that test. Tree dragging was verified in Edit mode, disabled in View mode, and retained when switching away and back to the same layout.
- The Vite-only chat request returned 404 for `/api/chat`, as expected without the Vercel function runtime. This is not a successful live-chat test.
- Production build reports an ONNX Runtime `eval` warning and a large JavaScript chunk warning. Neither fails the build, but bundle splitting and the dependency warning should be reviewed.
- The repository has no configured lint or test script. “No errors anywhere” cannot be certified from a successful build and a few manual UI checks alone.

## 6. Suggested next steps

1. **Add a real test baseline:** unit tests for chunking, retrieval, import validation, graph-ID resolution, merge payload validation, and working-copy edits; add mocked endpoint tests that never require provider credentials.
2. **Verify the live AI path:** run the 5 checks in §4 using a development/deployment environment, record the provider/model and observed limits, and keep keys server-side.
3. **Complete correction UX:** show correction candidates clearly, let the user review a diff, and only then apply changes to the working copy. Keep this separate from automatic mutation.
4. **Make session state durable:** add explicit save/restore or IndexedDB/localStorage persistence for the working copy, chat transcript, and optionally Tree positions. Keep large embeddings out of synchronous localStorage.
5. **Harden imports and merges:** validate the entire schema, check IDs and connection endpoints, cap payload sizes, and map custom-insight anchors to surviving merged topics/subtopics.
6. **Scale and polish:** measure 50–100+ node layouts, lazy-load Transformers.js/ONNX to reduce the initial bundle, inspect the ONNX warning, and do focused keyboard, screen-reader, mobile, and contrast checks.
7. **Revisit docs and scripts:** align the older PRD/TRD build checklist with the current d3-force/React Flow implementation and replace the legacy manual scripts' missing `test-data/` assumption with reproducible fixtures or safe mocks.

## 7. Local commands

```powershell
npm install
npm run dev
npm run build
vercel dev
```

`npm run dev` is for frontend iteration; it does not exercise Vercel API functions. `vercel dev` is the local integration path for `/api/*`. Avoid running the legacy endpoint scripts against a live provider without reviewing their inputs and confirming credentials/cost expectations.
